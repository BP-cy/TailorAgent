# 代码审查

当用户希望审查代码改动时，按以下流程进行：

1. 用 Bash 执行 `git status` 与 `git diff`（必要时 `git diff --staged`），了解本次改动范围。
2. 对每个改动文件，用 Read 工具读取关键上下文，重点检查：
   - **正确性**：边界条件、空值、并发、资源释放、异常处理；
   - **安全**：注入、路径穿越、凭据硬编码、越权；
   - **可维护性**：命名、重复代码、与既有约定是否一致（本项目注释与界面文案用中文）。
3. 输出一份审查报告，按「🔴 严重 / 🟡 建议 / ⚪ 可选」分级，每条给出：
   - `文件:行号`、问题描述、具体修改建议。
4. 不擅自改动代码，除非用户明确要求；如要改，先说明思路再动手。

保持结论可执行、可定位，避免泛泛而谈。
